> 状态：设计稿（待实现）
> 日期：2026-10-16
> 涉及：`src/App.tsx`、`src/pages/PublishEditorPage.tsx`、`src/pages/PublishContentPage.tsx`（新建）、`src/components/SpotContentPanel.tsx`（新建）、`src/components/SpotRelativeMap.tsx`（新建）、`src/lib/aiDraft.ts`、`src/lib/amapLocate.ts`、`src/types/attraction.ts`、`src/components/PublishSpotMap.tsx`（零改动）、`docs/design.md`

## 1. 拆分动机

现在的阶段二一屏干三件事：定坐标（高德定位）、写文案（AI）、排内容（排序 / 传图 / 改字），点一次「AI 生成并定位」全串在一个 handler 里（[PublishEditorPage.tsx:263](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/PublishEditorPage.tsx#L263)）。五个后果：

1. **坐标和文案互相绑架**。重跑内容会顺带重跑定位，反过来也一样，两个环节没法独立重试。
2. **失败无法分开重试**。AI 挂了走 mock 模板时坐标已经定完；高德限流时文案又已经生成，用户不知道该重试哪一半。
3. **地图和文案抢屏幕**。左栏同时挂「节点列表 + 内容表单」，小屏下要滚很久才能看到内容。
4. **定位没有独立入口**。现在只有"生成并定位"这一个总开关，想单独把节点坐标对齐到高德、或单独重写文案，都做不到。拆分后定位单独成按钮，逻辑仍复用原来那一段。
5. **起点被静默改写**。`locateAttractionOnMap` 结尾把 `start` 覆盖成 `spots[0]`（[amapLocate.ts:333](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/amapLocate.ts#L333)），用户拖好的绿色游客起点会悄悄跑掉。拆开后定位由阶段二单独触发，调用方只取 `spots`、不回写它返回的 `start`，问题在调用方消失。

拆分后的原则一句话：**坐标在前、由人定；文案在后、由 AI 写**；内容是**从地图工作台进去的一个独立页面**，随时能退回来重新拖节点。

```
   阶段一                阶段二（主工作台）              阶段三（独立页面）
┌──────────┐        ┌──────────────────────┐        ┌──────────────────┐
│ 确定范围 │   →    │    地点与内容        │ 内容创作→│    内容创作      │
└──────────┘        └──────────────────────┘        └──────────────────┘
                          ↑                                  │
                          └───────────── 返回 ───────────────┘
```

## 2. 目标结构

| 阶段 | 名称 | 承载 | 产出 | 主要交互 |
|---|---|---|---|---|
| 一 | 确定范围 | 路由 `/publish/:id` | `name` / `city` / `areaPoi` / `amapContext` / `candidates[].picked` | 填名称与城市 + 「检索景区」 + 看「相对位置」画布 + 勾候选 |
| 二 | 地点与内容（地图选点工作台） | 路由 `/publish/:id` | `spots[].{id,name,lng,lat,searchHint}`、`start`、`zoom` | 勾候选 / **按名称定位** / 手动加点 / 拖标记 / 排序 / 定起点 / 看路线 / **发布** |
| 三 | 内容创作 | 路由 `/publish/:id/content` | `description` / `spots[].{poetic, slides[0], image}` | AI 写简介 + 讲解 + 逐节点改文案 / 传图 + 发布 |

全局不变式：**坐标只能在阶段二改**（内容页不挂地图、也不碰坐标）；阶段二不改文案。**景点简介（`description`）不在阶段一收集**，改由阶段三的「AI 生成讲解」顺带写出来、并可在内容页手改（见 §5 第 10 条）。
**发布按钮阶段二和内容页都有**（已拍板，见 §5）：内容页随时能退回阶段二调坐标，所以阶段二不必被挡在发布之外；**但阶段二的「发布」要求全部节点都写过文案**（见 §5 第 8 条）。

- **每个点都带名称**（2026-10-17 加）：主景点 12px/600/`#111827`，候选点 11px，已勾选 `#111827`、未勾选 `#9ca3af`；文字带底色调描边（`paint-order: stroke`）以便在重叠处仍可读；靠近右缘时标签自动翻到点的左侧
- **在画布上直接选点**（2026-10-17 加）：点圆点即切换该候选的 `picked`（热区半径 13px，比圆点大一圈；鼠标悬停有 `title` 提示），写回的还是 `draft.candidates`，所以与候选列表的勾选框**双向同步**
- 数据源：`draft.areaPoi`（主景点）+ `draft.candidates`（候选点，勾选状态实时反映）
- 空态：未检索时显示 `检索景区后，这里显示主景点与候选点的相对位置`

### 2.3 阶段三 · 内容创作（独立页面，沉浸式、不挂地图）

新路由 `/publish/:id/content`，独立页面组件，自己一套页头：

- 页头左：**`调整地点`**（不是「返回」）→ 回到 `/publish/:id`（阶段二），回去后节点重新可拖
- 页头中：景点名 + 节点数
- 页头右：**`AI 生成讲解`** + **`发布`**
- 正文两栏，**不挂地图**：
  - 左栏窄（约 260px）：**节点列表**，序号 + 名称 + 是否已写文案的标记，点击切换当前节点
  - 右栏宽：选中节点的**内容表单**，居中限宽（`max-w-3xl`）纵向排布 —— 名称 / 诗意副标题 / 实景图上传 / 讲解标题 / 要点 / 口播文案（现有面板原样搬过来，[PublishEditorPage.tsx:795](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/PublishEditorPage.tsx#L795)）
- 整页只干一件事：写内容。地图、拖拽、路线按钮都不出现在这一页
- **支持 `?spot=<节点 id>` 定位**（2026-10-17，见 §5 第 15 条）：带这个查询参数进来就直接把该节点设为当前节点（参数指向的 id 不存在时回落第 1 个节点）；不带参数仍默认第 1 个。左栏自己的点击切换**不改 URL**，所以参数只在"从阶段二跳进来"时起作用
- `spots.length === 0` 时（直接敲 URL 进来）重定向回 `/publish/:id`

`AI 生成讲解` 的行为：按已定节点**按 index 一一对应**写内容，**不新增 / 不删除 / 不移动节点**，也不动坐标。

点「调整地点」回阶段二后：地图上的节点重新可拖、起点可挪、还能再点「按名称定位」—— 也就是"内容写了一半发现坐标不对"可以退回去改，不会丢文案（文案存在草稿里）。

## 3. 路由与草稿状态

`src/App.tsx` 加一条路由：

```tsx
<Route path="/publish/:id" element={<PublishEditorPage />} />
<Route path="/publish/:id/content" element={<PublishContentPage />} />   // 新增
```

两个页面都从 `ensureEditableDraft(id)` 读同一份 `localStorage` 草稿，所以来回切换不丢状态。

`DraftAttraction` 加一个草稿态字段：

```ts
export interface DraftAttraction {
  // …现有字段
  /** 阶段一/二里上次停在哪一步，进入 /publish/:id 时恢复；草稿态字段，不进发布契约 */
  lastStage?: 1 | 2
}
```

- 阶段三是独立路由，落点由 URL 决定，所以不需要 `3`。
- 进入 `/publish/:id`：`setStage(item.lastStage ?? (item.spots.length > 0 ? 2 : 1))`。存量草稿没有该字段，落到 `spots.length` 推断。
- 加这个字段是为了覆盖"阶段二里把节点全删了然后刷新，应该还留在阶段二"这种边界；如果你觉得不值得加字段，去掉它、纯用 `spots.length` 推断也能跑。

**不需要在导出时剥离**：`draftStore.toPublishedPackage` 是逐字段构造 `pkg` 的（[draftStore.ts:269](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/draftStore.ts#L269)），草稿字段本来就不会进发布包。这点和 `searchHint` 不同 —— `searchHint` 长在 `Spot` 上，而 `Spot` 会整条进包，才需要显式剥掉。

### 4.7 AI 内容生成：新增 fillSpotContent（src/lib/aiDraft.ts）

```ts
export type FillContentInput = {
  name: string
  description: string
  city?: string
  amapContext?: string
  /** 阶段二定好的节点，只取名称作输入 */
  spots: Array<{ name: string }>
}

export type FillContentResult = {
  /** 与 input.spots 按 index 一一对应 */
  contents: Array<{ poetic: string; slides: Slide[] }>
  /** 景点简介；AI 没给就留空、由人写（阶段一已不再收集简介） */
  description?: string
  source: 'ai' | 'mock'
  reason?: string
}
```

关键约束：

- **按 index 一一对应回填**，函数**不接收也不产出坐标与名称**。名称是阶段二的产物，AI 只把它当输入；这样用户在阶段二改过名字也不会被 AI 覆盖。

- **同一份输出里顺带写 `description`**（2026-10-17 加）：JSON 顶层多一个 `"description"`（约 80～120 字、面向列表与封面、不用"第几站"这类导览用语），解析后放进 `FillContentResult.description`；AI 没给或走 mock 时该字段为 `undefined`，内容页保留草稿里原值。
- 兜底：未配置 key 或请求失败时产出 `${name}是${景点名}的重要停驻点` 这类模板内容，并带 `reason`，由页面在 toast 里明示。
- **可删的旧代码**：`generateDraftSpots`、`alignToTargets`、`GenerateTarget`、`GenerateDraftInput` 拆分后没有调用方，一并删除（`mockSpots` 的兜底思路改写进 `fillSpotContent`）。
