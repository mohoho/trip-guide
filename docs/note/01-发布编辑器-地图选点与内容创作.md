> 状态：设计稿（待实现）
> 日期：2026-10-16
> 涉及：`src/App.tsx`、`src/pages/PublishEditorPage.tsx`、`src/pages/PublishContentPage.tsx`（新建）、`src/components/SpotContentPanel.tsx`（新建）、`src/components/SpotRelativeMap.tsx`（新建）、`src/lib/aiDraft.ts`、`src/lib/amapLocate.ts`、`src/types/attraction.ts`、`src/components/PublishSpotMap.tsx`（零改动）、`docs/design.md`

## 1. 拆分动机

现在的阶段二一屏干三件事：定坐标（高德定位）、写文案（AI）、排内容（排序 / 传图 / 改字），点一次「AI 生成并定位」全串在一个 handler 里（[PublishEditorPage.tsx:263](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/PublishEditorPage.tsx#L263)）。五个后果：

1. **坐标和文案互相绑架**。重跑内容会顺带重跑定位，反过来也一样，两个环节没法独立重试。
2. **失败无法分开重试**。AI 挂了走 mock 模板时坐标已经定完；高德限流时文案又已经生成，用户不知道该重试哪一半。
3. **地图和文案抢屏幕**。左栏同时挂「节点列表 + 内容表单」，小屏下要滚很久才能看到内容。
4. **定位没有独立入口**。现在只有"生成并定位"这一个总开关，想单独把节点坐标对齐到高德、或单独重写文案，都做不到。拆分后定位单独成按钮，逻辑仍复用原来那一段。
5. **起点被静默改写**。`locateAttractionOnMap` 结尾把 `start` 覆盖成 `spots[0]`（[amapLocate.ts:333](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/amapLocate.ts#L333)），用户拖好的绿色游客起点会悄悄跑掉。拆开后定位由阶段二单独触发，调用方只取 `spots`、不回写它返回的 `start`，问题在调用方消失。

拆分后的原则一句话：**坐标在前、由人定；文案在后、由 AI 写**；内容是**从地图工作台进去的一个独立页面**，随时能退回来重新拖节点。

```
   阶段一                阶段二（主工作台）              阶段三（独立页面）
┌──────────┐        ┌──────────────────────┐        ┌──────────────────┐
│ 确定范围 │   →    │    地点与内容        │ 内容创作→│    内容创作      │
└──────────┘        └──────────────────────┘        └──────────────────┘
                          ↑                                  │
                          └───────────── 返回 ───────────────┘
```

## 2. 目标结构

| 阶段 | 名称 | 承载 | 产出 | 主要交互 |
|---|---|---|---|---|
| 一 | 确定范围 | 路由 `/publish/:id` | `name` / `city` / `areaPoi` / `amapContext` / `candidates[].picked` | 填名称与城市 + 「检索景区」 + 看「相对位置」画布 + 勾候选 |
| 二 | 地点与内容（地图选点工作台） | 路由 `/publish/:id` | `spots[].{id,name,lng,lat,searchHint}`、`start`、`zoom` | 勾候选 / **按名称定位** / 手动加点 / 拖标记 / 排序 / 定起点 / 看路线 / **发布** |
| 三 | 内容创作 | 路由 `/publish/:id/content` | `description` / `spots[].{poetic, slides[0], image}` | AI 写简介 + 讲解 + 逐节点改文案 / 传图 + 发布 |

全局不变式：**坐标只能在阶段二改**（内容页不挂地图、也不碰坐标）；阶段二不改文案。**景点简介（`description`）不在阶段一收集**，改由阶段三的「AI 生成讲解」顺带写出来、并可在内容页手改（见 §5 第 10 条）。
**发布按钮阶段二和内容页都有**（已拍板，见 §5）：内容页随时能退回阶段二调坐标，所以阶段二不必被挡在发布之外；**但阶段二的「发布」要求全部节点都写过文案**（见 §5 第 8 条）。

### 2.1 阶段一 · 确定范围

左栏卡片「确定旅游范围」放**景点名称**、**城市 / 区域**，以及**主景区**三段：

- **原先的「简介」文本框已删除**（2026-10-17，见 §5 第 10 条）—— 简介挪到内容创作阶段由 AI 写。
- **「主景区」并进这张卡片**（2026-10-17，见 §5 第 13 条）：`检索景区 / 重新检索` 按钮 + 主景区信息预览，从原来右栏那块独立面板搬过来，标题由「高德范围」改为**「主景区」**（因为它本来就只显示主景点）。
- **主景区预览只显示主节点信息**（2026-10-17，见 §5 第 11 条）：`pre` 里改成 `buildMainPoiText(draft.areaPoi)`（主景区名 / 行政区 / 类型 / 地址 / 坐标五行），不再把周边地点列表铺进预览；**喂给 AI 的 `amapContext` 仍是完整文本**（`buildAmapContextText` 不动），只是这一屏不再显示周边节点。
- **「主景区」按小标题排**（2026-10-17，见 §5 第 14 条）：`text-sm font-medium text-[#111827]`（原来跟输入框标签一样是 `text-xs text-[#9ca3af]`，太淡压不住这一段）；下面那行坐标的引导词由「起点」改为**「坐标」**。

右栏是**一张卡片、上下两段**（2026-10-17 合并，见 §5 第 17 条；此前是两张各自带边框的独立卡片，更早是左右两列）：

- 上段 **「候选地点」画布**（内部仍叫 `SpotRelativeMap`、文档里也常称「相对位置」小画布；屏上标题 2026-10-17 改为**「候选地点」**，见 §5 第 14 条）
- 下段 `CandidateList`：可勾选的完整候选明细，用 `border-t` 分段铺在画布下方，小标题 2026-10-17 由「附近候选地点」改为**「地点信息」**（见 §5 第 18 条）；每行是**名称一行 + 「地址 · 类型 · 距离」一行**（地址 2026-10-17 加、与类型距离同一行，见 §5 第 17/18 条）
- 列表底部那个按钮**按阶段二状态改名**（2026-10-17，见 §5 第 16 条）：`spots` 为空时是**「用勾选的候选生成节点」**，已有节点时变成**「更新节点」**，点了按当前勾选**双向同步**阶段二节点（取消勾选的删除、新勾选的追加、已有节点保留原名/坐标/文案、手加节点不受影响）

主按钮文案：`下一步：地点与内容 →`（**保留现名**，这一步对外仍叫「地点与内容」，不改成「地图选点」）

点「下一步」时如果阶段二**一个节点都还没有**，直接把当前勾选的候选带过去当节点（2026-10-17，见 §5 第 21 条）—— 再也不用先进阶段二、再回来点一次「用勾选的候选生成节点」。有节点时这一步什么都不做，勾选变化仍走列表底部那个「更新节点」按钮，两者不会互相覆盖。

**「相对位置」小画布**：把**主景点（主景区 POI）**和**已勾选的候选点**按经纬度差等比投影到一块小画布上，一眼看清谁离主景区近、相互方位与疏密。

- **只画主景点 + 已勾选的点**（2026-10-17，见 §5 第 12 条）：未勾选的候选不出现在画布上；取消选中后**用剩下的点重新拟合**包围盒再投影（点少了不是简单留白，而是整张图重新铺满）——所以画布同时是"已选总览"和"选点入口"
- 主景点：**实心大点红色 `#ef4444`** + 白描边，旁边标名称；已勾选候选：**实心小点蓝色 `#3b82f6`** + 白描边，带名称（两色 2026-10-17 定，见 §5 第 20 条）；**只有圆点换色，名称文字一律 `#111827`**（主景点粗体 600、候选 400）；点之间**不连线**
- **米白底 + 极淡方格 `#fcf9f2` / 格线 `#fdfcf8`**（2026-10-17 定；当天从 `#eef0f3` → 浅绿 `#e6f6ea` → 浅灰 `#f4f4f4` → 最终米白方格，见 §5 第 19 条）：方格由 CSS 两层 `linear-gradient` 画 1px 线得到（`backgroundSize: 15px 15px`，色值取自用户给的参考图，格线比底色只亮 3 个色阶），**不是渐变填充**，所以仍符合全站的纯色取向；标签描边（`paint-order: stroke`）取底色 `CANVAS_BG`，文字重叠处不会积出灰边（会把方格也挖空一点，属预期）。**不画地图底图、不请求瓦片**，纯本地绘制
- **画布尺寸**：高度固定 260px，**宽度取容器实测值**（`ResizeObserver`）并把 `viewBox` 设成同一组像素值 —— 早先固定 `viewBox="0 0 320 180"` 时，在 639px 宽的卡片里会被等比缩放居中，图只占中间 320px，看着"范围很小"
- **投影**：取所有点的经纬度包围盒**等比**缩放进画布内边距 20px；单点或共线时用固定半径兜底
- **每个点都带名称**（2026-10-17 加）：主景点 12px/600/`#111827`，候选点 11px，已勾选 `#111827`、未勾选 `#9ca3af`；文字带底色调描边（`paint-order: stroke`）以便在重叠处仍可读；靠近右缘时标签自动翻到点的左侧
- **在画布上直接选点**（2026-10-17 加）：点圆点即切换该候选的 `picked`（热区半径 13px，比圆点大一圈；鼠标悬停有 `title` 提示），写回的还是 `draft.candidates`，所以与候选列表的勾选框**双向同步**
- 数据源：`draft.areaPoi`（主景点）+ `draft.candidates`（候选点，勾选状态实时反映）
- 空态：未检索时显示 `检索景区后，这里显示主景点与候选点的相对位置`

### 2.3 阶段三 · 内容创作（独立页面，沉浸式、不挂地图）

新路由 `/publish/:id/content`，独立页面组件，自己一套页头：

- 页头左：**`调整地点`**（不是「返回」）→ 回到 `/publish/:id`（阶段二），回去后节点重新可拖
- 页头中：景点名 + 节点数
- 页头右：**`AI 生成讲解`** + **`发布`**
- 正文两栏，**不挂地图**：
  - 左栏窄（约 260px）：**节点列表**，序号 + 名称 + 是否已写文案的标记，点击切换当前节点
  - 右栏宽：选中节点的**内容表单**，居中限宽（`max-w-3xl`）纵向排布 —— 名称 / 诗意副标题 / 实景图上传 / 讲解标题 / 要点 / 口播文案（现有面板原样搬过来，[PublishEditorPage.tsx:795](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/PublishEditorPage.tsx#L795)）
- 整页只干一件事：写内容。地图、拖拽、路线按钮都不出现在这一页
- **支持 `?spot=<节点 id>` 定位**（2026-10-17，见 §5 第 15 条）：带这个查询参数进来就直接把该节点设为当前节点（参数指向的 id 不存在时回落第 1 个节点）；不带参数仍默认第 1 个。左栏自己的点击切换**不改 URL**，所以参数只在"从阶段二跳进来"时起作用
- `spots.length === 0` 时（直接敲 URL 进来）重定向回 `/publish/:id`

`AI 生成讲解` 的行为：按已定节点**按 index 一一对应**写内容，**不新增 / 不删除 / 不移动节点**，也不动坐标。

点「调整地点」回阶段二后：地图上的节点重新可拖、起点可挪、还能再点「按名称定位」—— 也就是"内容写了一半发现坐标不对"可以退回去改，不会丢文案（文案存在草稿里）。

## 3. 路由与草稿状态

`src/App.tsx` 加一条路由：

```tsx
<Route path="/publish/:id" element={<PublishEditorPage />} />
<Route path="/publish/:id/content" element={<PublishContentPage />} />   // 新增
```

两个页面都从 `ensureEditableDraft(id)` 读同一份 `localStorage` 草稿，所以来回切换不丢状态。

`DraftAttraction` 加一个草稿态字段：

```ts
export interface DraftAttraction {
  // …现有字段
  /** 阶段一/二里上次停在哪一步，进入 /publish/:id 时恢复；草稿态字段，不进发布契约 */
  lastStage?: 1 | 2
}
```

- 阶段三是独立路由，落点由 URL 决定，所以不需要 `3`。
- 进入 `/publish/:id`：`setStage(item.lastStage ?? (item.spots.length > 0 ? 2 : 1))`。存量草稿没有该字段，落到 `spots.length` 推断。
- 加这个字段是为了覆盖"阶段二里把节点全删了然后刷新，应该还留在阶段二"这种边界；如果你觉得不值得加字段，去掉它、纯用 `spots.length` 推断也能跑。

**不需要在导出时剥离**：`draftStore.toPublishedPackage` 是逐字段构造 `pkg` 的（[draftStore.ts:269](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/draftStore.ts#L269)），草稿字段本来就不会进发布包。这点和 `searchHint` 不同 —— `searchHint` 长在 `Spot` 上，而 `Spot` 会整条进包，才需要显式剥掉。

### 4.7 AI 内容生成：新增 fillSpotContent（src/lib/aiDraft.ts）

```ts
export type FillContentInput = {
  name: string
  description: string
  city?: string
  amapContext?: string
  /** 阶段二定好的节点，只取名称作输入 */
  spots: Array<{ name: string }>

export type FillContentResult = {
  /** 与 input.spots 按 index 一一对应 */
  contents: Array<{ poetic: string; slides: Slide[] }>
```

关键约束：

- 兜底：未配置 key 或请求失败时产出 `${name}是${景点名}的重要停驻点` 这类模板内容，并带 `reason`，由页面在 toast 里明示。

## 5.1 景点管理页改成列表 + 删除（2026-10-17）

`/publish`（景点管理）这一屏原来抄的是前台首页的样子：顶部一张 featured 大图 + 三列卡片。现在改成**一行一个景点**的列表，并把「删除」补齐。

- **去掉 banner**：`PublishListPage` 里那张 `min-h-[280px]` 的大图连同 `featured` 变量一起删掉；空列表时直接给「创建第一个景点」的虚线框（原来靠"没有 featured"判断，现在靠 `rows.length === 0`）。
- **一行 = 缩略图 + 名称 + 模式标 + 状态标 + 简介 + 节点信息 + 删除**：缩略图 102×68（`rounded-xl`）；名称后面接 `ModeTag`（故事实心 / 打卡描边）与 `已发布 / 草稿`；简介 `truncate` 一行；节点信息**最多三行**（`line-clamp-3`，2026-10-17 用户标注「这里可以宽裕点，最多三行」——原来 `truncate` 只能一行，11 个节点的名字必然被截掉大半）。
- **节点信息**（用户选「两者都要」）：`N 个节点 · 已编辑 x / 未编辑 y · 节点名 → 节点名 → …`。「已编辑」沿用编辑器同一口径 `isSpotPlaceholder`（空要点 / `待完善讲解要点` / 只剩 `地址：` 行 = 未编辑，见 §5 第 5 条），所以管理页和编辑器里看到的数字必然一致；0 个节点时只写「暂无节点」。节点名跟着统计后面自然折行，最多三行，行高随内容变（11 个节点那行 95 → 112px，缩略图仍垂直居中）。
- **故事包不写链条，写分叉**（2026-10-17 用户标注「故事模式 这里要显示多分支」）：打卡包的走法就是数组顺序，`A → B → C` 是它的真相；故事包的真相是**谁的下一个有几个**，再摊成一条链就是错的（红山动物园 11 个节点看着像直线，其实入口猴山一上来就三岔）。所以 `mode === 'story'` 时第三个字段换成 `storyBranchOutline()`（`src/lib/storyTour.ts`）产出的**每个分叉点一行 + 末行收结局**：
  - `入口 猴山 → 南京红山动物园-新狼馆 / 南京市红山森林动物园本土物种保育区 / 细尾獴馆 · 结局 红山森林动物园-新虎园`；
  - 规则：遍历 `spots`，**生效去向 ≥ 2 个**的节点各出一行（用 `storyNextChoices` 的生效值，所以没连过线的节点不算分叉点），入口那行前缀「入口」，去向按 `/` 并列；末尾把生效去向为 0 的节点收成 `结局 X、Y`；
  - **没有分叉（或没有分支表）时返回空数组**，回落到原来那条线性链条 —— 纯线性故事本来就该那么写。这样写死的分叉标在别的包上不会凭空捏造分支；
  - **入口单出一段**（2026-10-17 补）：分叉点不在入口时（真实数据里分叉发生在澳洲区），前面先给一段 `入口 猴山`，否则读起来像故事从澳洲区开始；入口自己就是分叉点时并进那一行，不重复；
  - 分叉行与统计行仍在同一个 `line-clamp-3` 的 `<p>` 里，段间用 ` · ` 分隔，所以排版、行高、三行上限全部照旧（红山那行实测一行 16.5px、行高 95px）。
- **节点数据从哪来**（`buildRows`）：本地草稿优先（编辑中的状态更新鲜），否则**现读发布包** `loadPublishedAttraction(id)` 取 `spots` **与 `story`**；读失败（包没了 / 手工删过）不报错，按「暂无节点」显示。因为要读包，列表构建改成 async（`reload()` 里 `loadCatalog().then(...).then(setRows)`），catalog 挂掉时仍退化成"只列本地草稿"。
- **删除**（用户选「移到 .trash 可恢复」）：
  - 纯本地草稿 → 老一套 `deleteDraft`（只动 `localStorage`）。
  - 已发布景点 → **新接口 `DELETE /__trip_guide/spot?id=…`**（`vite-plugin-export-to-display.ts`）：把 `public/spots/{id}.json` 与 `public/spots/{id}/`（图片目录）**移进 `./.trash/spots/{id}/`**，再从 `catalog.json` 里摘掉，返回 `{ trashDir, trashed }`。**`public/spots` 因此始终等于"当前已发布"**。同一 id 二次入 trash 时目录加时间戳后缀避免覆盖；`id` 先过 `^[A-Za-z0-9][A-Za-z0-9._-]*$`、并挡掉 `catalog`，所以没有路径穿越（实测 `../evil`、`a/b`、`catalog`、空 id 都是 400）。
  - 删之前走**行内二次确认**：垃圾桶按钮 → 变成「取消 / 确认删除」（红底），确认中按钮 `disabled`；成功后 toast（已发布的会提示"可在页面底部恢复"）。已发布景点删除时**连本地草稿一起删掉**，否则它会以"本地草稿"的身份重新出现在列表里。
  - 开发服务不可用（打包后的静态站点）时接口 404，toast 报错、本地草稿不动 —— 与发布时的"回落下载"不同，删除没有离线方案，宁可失败也不假装成功。
- **恢复**（同一屏，2026-10-17 用户问「有地方给我恢复吗」后补）：
  - 列表底部多一块**「已删除」**：`GET /__trip_guide/trash` 列出 `.trash/spots` 下的目录（每条显示名称、模式标、id、删除时间），右侧一个「恢复」按钮 → `POST /__trip_guide/trash/restore?folder=…`：把包 JSON 与图片目录**搬回 `public/spots`**、目录清空、`catalog.json` 里**按 `publishedAt` 插回原位置**（不是无脑塞到最前面），然后 `reload()` 让列表与前台同时回来。
  - 接口不可用（`GET` 404 / 抛错）时**静默不显示这一块**（`listTrashedSpots` 吞错返回空数组），所以打包后的静态站点上这块自然消失，不是坏掉。
  - `public/spots` 里已存在同名 id 时拒绝恢复（报"先把它删掉或改名再恢复"），不覆盖现有数据；`folder` 同样过 id 正则 + 前缀校验（实测 `../spots`、不存在的目录都是 500 且不落任何文件）。
  - **`localStorage` 里的草稿是恢复不了的**（删除时就删了，草稿没有回收站）—— 恢复回来的是**最后一次发布的包**，若删之前有没发布的编辑，那部分丢了。

## 6. 验证清单（浏览器）

1. 新建景点 → 阶段一左栏填名称 / 城市（**没有简介输入框**）→ 点左栏卡片里的「检索景区」→ 卡片底部**「主景区」**段出现主景点信息，右栏**「相对位置」小画布**出现（主景点黑色实心大点带名字、已勾选候选实心小点带名字、纯色底 `#eef0f3`、不出现地图瓦片），下方是全宽候选列表 → 点「下一步：地点与内容」。
2. 阶段二勾 3 个候选 → 生成节点 → **点「按名称定位」**：坐标被高德刷新（行为与原来「AI 生成并定位」的定位环节一致）、提示里给出 `已定位 N/M`、**`start` 保持没变**。
3. 回阶段一（点 tab）看画布：**只画主景点 + 已勾选的点**，勾新候选多一个点、取消候选少一个点且整张图重新铺满；未检索时显示空态文案。再回阶段二。
   - 画布**占满卡片宽度**（`viewBox` 等于容器像素宽 × 260），不再缩在中间一条；**每个点旁边都有名称**；
   - 直接点画布上的圆点 → 该候选勾选状态翻转，右侧候选列表的 `N/M` 与勾选框同步跟着变；
   - 左栏「主景区」预览里**只有主景点那几行**（名 / 行政区 / 类型 / 地址 / 坐标），不出现周边地点；**页面上不再有叫「高德范围」的标题**。
4. 阶段二点「+ 手动加点」，确认新节点落在**当前地图中心**（先把地图拖到别处再点，验证不是固定落在 `start`）。
5. 阶段二拖动一个节点、拖绿标设起点、切「显示路线」看步行连线 → 刷新页面，确认仍在阶段二且以上都保留。
6. 点「内容创作 →」进内容页 → 右栏出现**「景点简介」卡片** + 节点内容 → 点「AI 生成讲解」→ **简介被 AI 写入、各节点出现讲解标题 / 要点 / 口播**；**这一页不应出现地图**，是沉浸式两栏写作布局。
7. 内容页点「调整地点」→ 回到阶段二，确认节点位置与起点**与离开前完全一致**（关键回归点），且**重新可拖**；再拖一次 → 再进内容页，确认文案还在、坐标是刚拖过的新值。
8. 内容页改文案、传图 → 发布 → 前台 `/` 打开该景点，完整走一遍导览。**再回阶段二点一次「发布」**，确认阶段二也能直接发、且发出去的是当前坐标与起点。
9. 边界：
   - 阶段二 0 个节点时「内容创作」禁用；「按名称定位」在 0 节点时禁用；
   - 阶段一未检索时「相对位置」画布显示空态；只有一个点时也不炸（固定半径兜底）；
   - 手动加的「节点 N」定位大概率失败（关键词无意义），确认失败的节点落到主景区附近的兜底位置（**沿用原来的行为**），且不会把已拖好的其它节点挪走；
   - 直接访问 `/publish/<id>/content` 且该草稿 0 节点 → 重定向回 `/publish/<id>`；
   - AI 未配置时走模板内容并在 toast 里给出原因（**模板不产出简介，简介需自己补**）。
10. 阶段二起点与发布门控（2026-10-17 加）：
   - 页头只有 `上一步 / 发布`，全场**没有**「以选中节点为起点」按钮；内容创作入口在左栏底部；左栏**没有**「阶段一已选地点」块；
   - 拖地图上的绿色「起」标记 → `start` 跟着变（唯一改起点的途径）；
   - 刚生成的候选节点（`bullets` 只有 `地址：…`）显示 **未编辑**，且「发布」禁用；把全部节点写完 → 列表头 `已编辑 N/M` 满格、「发布」可点；

12. 候选列表按钮的双向同步（2026-10-17 加）：
   - `spots` 为空 → 按钮写「用勾选的候选生成节点」；已经有节点 → 写「更新节点」；
   - 已有 11 个节点、只勾 7 个候选时点「更新节点」→ 节点变 7 个（多出来的 4 个被删），剩下的名字 / 顺序 / 坐标不变，toast 报「移除 4 个」；

11. 阶段一画布联动与面板合并（2026-10-17 加）：
   - 画布上**只有主景点 + 已勾选的点**（未勾选的一个都不画）；
   - 点某个点取消选中 → 该点消失，**其余点重新铺满画布**（位置会变，不是留白）；再点回选中 → 恢复；

13. 「下一步」的自动生成（2026-10-17 加）：
   - 勾 3 个候选 → 直接点「下一步」（没进过阶段二）→ 阶段二**已经有 3 个节点**，名称与勾选一致、坐标就是候选的坐标（`searchHint` 已写上）、toast「已用勾选的 3 个候选生成节点」；
   - 在阶段二调过坐标 / 改过名字后回阶段一点「下一步」→ 节点**纹丝不动**（不重生成、不重复追加）；
   - 一个候选都没勾时点「下一步」→ 不报错、阶段二空态提示照常。
14. 景点管理页列表与删除（2026-10-17 加，见 §5.1）：
   - `/publish` 顶部**没有大图**，每个景点一行（缩略图 + 名称 + 模式标 + 状态标 + 简介一行 + 节点信息最多三行 + 垃圾桶）；
   - 当节点较多时（如 11 个）节点名**换行显示而不是被截成一行**，最多三行；
   - 已发布景点的节点信息**能读出来**（走 `loadPublishedAttraction`）：「N 个节点 · 已编辑 x / 未编辑 y · 名称 → 名称…」，与编辑器列表头的「已编辑」数字对得上；
   - **故事包的第三个字段是分叉不是链条**（2026-10-17 加）：红山动物园那行显示 `入口 猴山 → 新狼馆 / 本土物种保育区 / 细尾獴馆 · 结局 新虎园`，不再是一条 11 个名字的直线；打卡的乐山大佛 / 豫园仍是 `A → B → C`；
   - 有本地草稿的景点用草稿里的节点（不是旧包），0 节点的草稿显示「暂无节点」；
   - 点垃圾桶 → 行内出现「取消 / 确认删除」；点取消回到垃圾桶图标，什么都没发生；

   - 在「已删除」里点「恢复」→ 文件搬回 `public/spots`、`catalog.json` 按 `publishedAt` 插回原位置、列表与前台同时回来（该景点的**本地草稿不会回来**，编辑器会从发布包载入）；
   - 恢复一个 `id` 已存在的景点 → 报「先把它删掉或改名再恢复」，现有数据不被覆盖；
   - 确认删除**纯本地草稿** → 只在 `localStorage` 里消失，`public/spots` 一点没动，也不进「已删除」。
