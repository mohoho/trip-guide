# 故事模式：在「打卡模式」之外加一种分支叙事

> 状态：设计建议（待拍板）
> 日期：2026-10-17
> 涉及：`src/lib/tourPackage.ts`、`src/types/attraction.ts`、`src/lib/draftStore.ts`、`src/pages/TourPage.tsx`、`src/components/AmapLiveMap.tsx`、`src/components/TourProgressBar.tsx`、`src/pages/PublishEditorPage.tsx`、`src/pages/PublishContentPage.tsx`、`src/components/SpotContentPanel.tsx`、`src/lib/aiDraft.ts`（可选）、`docs/design.md`

## 1. 两种模式的产品边界

| 维度 | 打卡模式（现状） | 故事模式（新增） |
|---|---|---|
| 走法 | `spots` 数组顺序，线性走完 | 每个节点给 2~3 个去向，由人当场选 |
| 结构的唯一真相 | 数组**顺序** | 节点间的**关系**（谁的下一站有谁） |
| 讲解触发 | 抵达即讲 | 同左，不区分 |
| 结束 | 走到最后一站 | 走到**没有去向**的节点（结局） |
| 地图表现 | 全部节点按 1..N 铺出、进度条给总站数 | 只露"已知"的（已走过 / 站在哪 / 下一步能去哪） |
| 内容创作量 | 每节点 1 段讲解 | 每节点 1 段讲解 + 每个去向 1 行选项文案 |
| 适合的场景 | 一个园区、一条街，走完为止 | 两小时逛不完、有明显"向左还是向右"的场域 |

一句话：**打卡是清单，故事是地图**；到了故事模式里，"顺序"退化成"主线建议"，不再是走法的真相。

模式名沿用你说的两个词，发布端就叫 `导览模式：打卡 / 故事`，默认打卡。

## 2. 数据模型

### 2.1 核心决定：不加新节点类型，只加一张「去向表」

推荐（方案 A）：包顶层加两个 **optional** 字段。

```ts
export type TourMode = 'checkin' | 'story'

export interface StoryChoice {
  /** 去向节点 id */
  to: string
  /** 选项按钮上的字，如「往东 · 石阶向下」 */
  label: string
  /** 一行小字（可选），如「约 80 米 · 5 分钟」 */
  note?: string
}

export interface StoryGraph {
  /** 入口节点 id；缺省 = spots[0] */
  entry?: string
  /** key = 出发节点 id，value = 可选去向（建议 1~3 个）；无 key 或空数组 = 结局 */
  choices: Record<string, StoryChoice[]>
  /** 结局节点的标题（可选），纯展示，如「结局 · 井边无人」 */
  endings?: Record<string, string>
}

export interface PublishedAttraction {
  // …现有字段一个都不动
  mode?: TourMode
  story?: StoryGraph
}
```

三条理由：

1. **`spots` 一个字段都不动** —— 坐标、图片、讲解、`prepareMedia` 素材落盘、AI 生成、发布链路全部照旧复用；故事包与打卡包共用同一份节点数据，切模式不需要迁移节点。
2. **两个字段都是 optional** —— 存量三个包（红山动物园 / 乐山大佛 / 豫园）不改一个字节仍能加载，见 §5。
3. **分支是"关系"不是"节点属性"** —— 单独一张表可以一次性整体校验（悬空 `to`、孤立节点、自环都扫得出来）；挂在每个节点上则要遍历全表才能回答"谁到得了谁"。

备选（方案 B）：`Spot.choices?` 挂在节点上。编辑时更就近，但 `spots` 数组顺序的语义会被悄悄改写（打卡靠顺序、故事不靠同一个字段），而且 `Spot` 是整条进发布包的，加字段就是改契约。**不推荐**。

备选（方案 C）：`story.nodes` 另起一套故事节点。会和 `spots` 重复一份坐标 / 图片 / 讲解，素材落盘要照顾两处映射。**不建议**，除非以后要做"同一个景点、两套讲解"。

### 2.2 一个关键洞察：打卡是故事的特例

"打卡 = 每个节点只有一个去向（下一个）"。

所以运行期只写**一条图遍历**代码：

```
next = 去向 > 1  ? 停下等人选
     : 去向 = 1  ? 直接走那一个
     :           结束（结局）
```

打卡包的 `story` 缺失 → 运行时按数组顺序**隐式串链**（`i → i+1`，最后一站即结局）。这样换来三件事：

- `TourPage` 不需要 `if (mode === 'story')` 两套走法，只有一套遍历 + 少量界面差异；
- `mode` 只决定**界面表现**（要不要序号 / 要不要迷雾 / 进度条什么形态），不决定能不能走；
- 故事包的 `story` 写坏了（比如 `entry` 指向不存在的 id）可以**降级成打卡顺序**照常导览，不白屏。

（这条如果同意，§3 的改动量直接小一半 —— 它是整个方案里最省事的一刀。）

### 2.3 发布包里长什么样（举例）

以红山动物园改成故事版为例：

```json
{
  "mode": "story",
  "spots": [/* 11 个节点，结构与现在完全一致 */],
  "story": {
    "entry": "spot-mvaxdqn7-1",
    "choices": {
      "spot-mvaxdqn7-1": [
        { "to": "spot-mvaxdqn7-3", "label": "往东 · 去看袋鼠", "note": "约 120 米 · 3 分钟" },
        { "to": "spot-mvbb28ds-9", "label": "往西 · 考拉馆", "note": "约 200 米 · 5 分钟" }
      ],
      "spot-mvaxdqn7-3": [
        { "to": "spot-mvbb28ds-11", "label": "继续深入 · 虎园" }
      ]
    },
    "endings": { "spot-mvbb28ds-11": "结局 · 虎啸山林" }
  }
}
```

未出现在 `choices` 里的节点即结局（`spot-mvbb28ds-11` 也可以不写 `endings`，那就只有"故事结束"）。

## 3. 运行期（导览页）怎么走

### 3.1 走到一站：讲完 → 有多个去向就出选择面板

- 讲解面板下方弹出**「下一步去哪」**：每个去向一个按钮，显示 `label` + `note`；点一个 → `routeTo(该节点)`，路上把面板收起（复用 [TourPage.tsx:296](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L296) 的 `routeTo`）。
- **只有一个去向 → 不弹面板，直接走**。所以打卡包（或只连了一条链的故事包）用户完全感知不到新机制。
- **没有去向 → 结局**：这一段播完出「故事结束」卡片，复用 [TourPage.tsx:659](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L659) 那张 ending 卡，标题换成 `story.endings[id] ?? '故事结束'`，两个动作：`重新开始`（回 `entry`）/ `继续自由漫游`（即现在的 `exitAutoToManual`）。
- 手动模式同理：点节点或靠近触发（[TourPage.tsx:196](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L196) 的 `checkProximity`）讲完，有多去向就出面板，否则维持现状。

### 3.2 自动模式的语义要收窄（最重要的一条）

现在自动模式推进是 `nextChapter = chapter + 1`（[TourPage.tsx:386](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L386)）。故事模式下**遇到多分支必须停下等人选** —— 这是"自动模式自己乱走 / 绕死循环"的唯一防线：

- 去向 = 1：照旧自动走，等待节奏不变；
- 去向 > 1：`tourPhase` 停在 `presenting`，出选择面板，页头提示从「讲解中」改成「等你选一步」；选完立刻继续自动走 + 讲；
- 去向 = 0：进 `done`，出结局卡（现在的 `done` 逻辑不用改）。

副作用（好事）：**循环分支（A→B→A）天然安全** —— 自动不会自己绕圈，只有人能绕。

### 3.3 地图：从「全铺」改成「迷雾」

现状是一次性把 `spots` 全建成带序号 1..N 的 marker（[AmapLiveMap.tsx:150](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/components/AmapLiveMap.tsx#L150) + [AmapLiveMap.tsx:25](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/components/AmapLiveMap.tsx#L25)）。还没选就看见全部 11 个点，故事模式当场被剧透。

推荐做法：入参从 `spots` 扩成 `spots` + 一个**可见集合/状态**（`unknown | visited | current | reachable`），三层表现 —— 已走过（灰、不带序号）/ 站在哪（蓝）/ 下一步能去哪（黑 + 名称）；`unknown` 不建 marker。再给一个「显示全部」小开关，默认关（照顾"我就想看整个园区"的人）。

代价：`AmapLiveMap` 的 marker 生命周期要从"一次建成"改成"跟随集合增删"，约 20~30 行，顺带序号渲染按模式切换。

省事退路：**全部点照常显示、只是不显示序号**，改动最小，但故事感的悬念就没了。如果不接受迷雾，这是退路。

### 3.4 左栏「路线」面板 → 「足迹」

现状 [TourPage.tsx:686](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L686) 把 `nodes` 顺序列出 = 把整张分支图剧透光。

故事模式下改成**已走过的足迹**（按访问顺序），末尾接当前节点的「可选下一站」（可点，等同于点选择面板）。打卡模式保持现在的样子不变。

进度条：`TourProgressBar` 的游标是章节索引（[TourProgressBar.tsx:11](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/components/TourProgressBar.tsx#L11)），故事模式总站数未知 → 建议隐藏，或只显示「已走 N 站」。

## 4. 发布端怎么编

按现有不变式切分：**结构（谁能去哪）在阶段二，文案（选项上写什么字）在阶段三。**

### 4.1 阶段一：只加一行模式选择

左栏「确定旅游范围」卡片加一行 `导览模式：打卡 / 故事`，写进草稿 `mode`，默认打卡。**切换模式不动 `spots`** —— 两种模式共用同一份节点。

### 4.2 阶段二：分支编辑（本次工作量最大的地方）

三种做法，建议先做最省的：

| 方案 | 交互 | 代价 | 建议 |
|---|---|---|---|
| a 表单式 | 节点列表每行下挂一行「去向」：从其它节点里多选 + `设为入口` + `结局` 标记 | 纯表单，无地图交互，1 天量级 | **P0，先做** |
| b 地图连线 | 在图上从 A 拖到 B 形成分支 | 要 AMap 拖拽 / 命中检测 / 标签布局，3~5 天，移动端更难 | P1，可选 |
| c 只读分支示意图 | 复用 `SpotRelativeMap` 的投影思路，小画布画点 + 连线看懂结构 | 1~2 天 | P1，作为"看懂结构"的辅助 |

a 的最小形态（不动现有上下移动按钮）：

- 每行下挂：`去向` 多选（最多 3 个）+ `设为入口` + `结局` 标记；
- 列表头显示 `入口：X · 结局 N 个 · 孤立 0 个`；
- 没连过的节点按数组顺序隐式接下一个（§2.2），所以**只连一两处就能先跑起来**，不用把每个节点都连完。

### 4.3 阶段三：选项文案 + 结局标题

- `SpotContentPanel` 底部在故事模式下多一段**「分支文案」**：当前节点的每个去向一行，两个输入（`label` 必填 / `note` 选填）；
- 结局节点多一个「结局标题」输入（对应 `story.endings[id]`）。
- 去向的**目标**在阶段二定、这里只写字 —— 和"坐标在阶段二、文案在阶段三"是同一条规矩。
- `AI 生成讲解` 顺带产出这两样是可行的（输入里已经有每个去向的名字，见 [aiDraft.ts:150](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/aiDraft.ts#L150) 的 prompt），但**建议放到 P1**：选项文案很短、用户改写成本低，先把手工编辑跑通。

### 4.4 发布门控：在现有 `allWritten` 上加故事模式校验

现状是 `writtenCount === spots.length` 才能发（[PublishEditorPage.tsx:394](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/PublishEditorPage.tsx#L394)）。故事模式再加三条**硬**校验，不通过就禁用「发布」并在 `title` / toast 里指路：

1. `entry` 指向存在的节点（缺省 `spots[0]` 也算通过）；
2. 每个 `choices[x].to` 都指向存在的节点（无悬空引用）；
3. **没有孤立节点**：每个节点都能从入口走到（防止"精心写了一段永远到不了的讲解"）。

循环 / 自环（A→B→A、A→A）**不拦**（是玩法），只在列表里标一下让人自己知道。

## 5. 契约与兼容（必读）

- **不要动 `PACKAGE_SCHEMA_VERSION`。** `assertPublishedAttraction` 是严格相等判断（[tourPackage.ts:82](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/tourPackage.ts#L82)），一 bump，已发布的红山动物园 / 乐山大佛 / 豫园**立刻全部加载失败**。新增字段一律 optional。
- `mode` 缺失 = 打卡；`mode === 'story'` 但 `story` 缺失 / `entry` 悬空 = **按打卡顺序降级**，不要 throw。
- `assertPublishedAttraction` 里加故事模式的**软校验**（只对 `mode === 'story'` 生效）：坏了就 `console.warn` + 降级，**不在前台抛错** —— 前台白屏的代价远大于"降级成线性"。硬校验留在发布端（§4.4）。
- `toPublishedPackage` 是逐字段构造的（[draftStore.ts:280](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/draftStore.ts#L280)），记得把 `mode` / `story` 明确带过去，**漏了就会出现"编辑器里是故事版、发出去是打卡版"**。
- `DraftAttraction` 加 `mode?: TourMode` / `story?: StoryGraph`（草稿态，逐字段构造所以不会进契约，不用像 `searchHint` 那样显式剥离）。
- 素材链路（`prepareMedia` / `assets`）不涉及新素材，零改动。

## 6. 落地分期

**P0（最小可用，建议一轮做完）**

1. 契约加 `mode` / `story`（optional）+ 草稿字段 + `toPublishedPackage` 带上；
2. 阶段二：模式开关 + 表单式分支编辑（入口 / 去向 / 结局）+ §4.4 门控；
3. 阶段三：分支文案与结局标题编辑；
4. 前台：一条图遍历 + 多分支出选择面板 + 结局卡；**去向 ≤ 1 时的行为与今天完全一致**（这是回归基线）。

**P1**

5. 地图迷雾（可见集合）+ 左栏改「足迹」+ 隐藏/改造进度条；
6. `SpotRelativeMap` 画只读分支示意图；AI 顺带写分支文案与结局标题。

**P2**

7. 多结局收集（已解锁 N/M）、重复访问标记、分支上限提升、地图拖拽连线、分支专属配图。

## 8. 验证清单（浏览器）

1. 把探索草稿切到「故事」→ 阶段二列表头出现 `入口 / 结局` 信息；连一条 `A→C`（跳过 B）→ 只连这一处就能发布（其余按数组顺序隐式接链）。
2. 门控：把 C 的文案留空 → 「发布」禁用且提示指向 C；补完 C → 可发布。
3. 前台手动：走到 A → 讲完弹「下一步去哪」两个按钮 → 点 C → 走过去 → 讲 C → C 无去向 → 出「故事结束」卡 → 点「重新开始」回到 A。
4. 前台自动：A（两分支）讲完**停住**并提示「等你选一步」，不自动乱走；选完自动走 + 讲；结局后出结束卡。
5. **回归基线**：只有一个去向的节点不出面板，整条链的体验与今天的打卡导览看不出区别。
6. 迷雾：未选之前地图上只有「已走过 + 当前 + 可选下一站」，其余不出现；点「显示全部」后全部出现。
7. **兼容**：存量三个打卡包（红山动物园 11 站 / 乐山大佛 / 豫园）前台打开一切正常（`mode` 缺失 → 打卡）。
8. **降级**：把某个故事包的 `story` 手工删掉再打开 → 按顺序线性走完、不白屏、控制台有 warn。
9. 孤立节点：造一个谁都到不了的节点 → 阶段二发布被拦；手改 JSON 绕过校验 → 前台忽略它、不卡死。

## 9. 明确不动的东西

- **打卡模式的全部现有行为**：线性走法、抵达即讲、进度条、左栏路线面板；
- `spots` / `Spot` / `Slide` 的结构，以及 `prepareMedia` / `assets` 媒体落盘；
- 阶段一「候选地点」画布与候选列表、高德检索与「按名称定位」；
- `publishDraft` 与 `public/spots` 落盘链路；`/` 与 `/tour/:id` 的路由；
- 「问 AI」问答不受模式影响。
