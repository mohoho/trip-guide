## 0. 已拍板（2026-10-17 · 前台故事模式长什么样）

发布端怎么编分支、地图要不要迷雾这些还待定（§7），但**前台故事页的形态**已经定死：

1. **打卡与故事是两种独立页面。** 不再是"同一个 `TourPage` 里 `if (mode === 'story')`"——前台按包的 `mode` **选页面组件**（`mode` 缺失 = 打卡页原样）。故事页参考打卡页写，复用地图 / 语音 / 定位 / 路径动画这些底座能力，但**页面骨架与推进逻辑自成一派**。
2. **故事模式没有自动模式。** 页面上**不出现**「手动 / 自动」切换，也不存在自动巡航：没有"选完自动走过去、到站自动讲、讲完自动下一站"那条链路。
3. **一切都靠用户点左下角的选项。** 左下角是**去向选项面板**（每个可选去向一个按钮）；**即使是单路径（只有一个去向）也要用户点「下一步」**，不自动前进。也就是说：**推进的唯一动力是人点按钮**。
4. **右上角是当前情节。** 右上角常驻一块**当前情节面板**（节点名 + 讲解正文），作为故事页的信息重心，替代打卡页把内容塞在底部卡片的做法。
5. **情节需要语音播报。** 进入一个节点（首次抵达，或点选项走过去之后）就播报该节点情节，沿用打卡页那套 `speak()`（`window.speechSynthesis`）。
6. **不回头。** 左下角只列**没去过**的去向；想重走已走过的地方，就点「重新开始」回入口（2026-10-17 追加拍板，§3.3 第 5 条）。

即：**故事页 = 地图打底 + 右上角情节 + 左下角选项**，没有自动、没有自动前进、单路径也要点下一步、走过的路不再出现。

## 1. 两种模式的产品边界

| 维度 | 打卡模式（现状） | 故事模式（新增） |
|---|---|---|
| 走法 | `spots` 数组顺序，线性走完 | 每个节点给若干去向（不设个数上限），由人当场选 |
| 推进方式 | 手动 / 自动两种巡航，到站即讲、讲完自动下一站 | **没有自动模式**；每一步都由人点左下角选项，**单路径也要点「下一步」** |
| 页面 | `TourPage` 一个组件 | **独立的故事页组件**（与打卡页是兄弟，不是 `if` 分支） |
| 讲解落点 | 底部卡片 | **右上角「当前情节」面板** |
| 讲解触发 | 抵达即讲 + 可自动前进 | 进入节点即**语音播报**，播完**等用户点选项**才动 |
| 结构的唯一真相 | 数组**顺序** | 节点间的**关系**（谁的下一站有谁） |
| 结束 | 走到最后一站 | 走到**没有去向**的节点（结局） |
| 地图表现 | 全部节点按 1..N 铺出、进度条给总站数 | 只露"已知"的（已走过 / 站在哪 / 下一步能去哪） |
| 内容创作量 | 每节点 1 段讲解 | 每节点 1 段讲解 + 每个去向 1 行选项文案 |
| 适合的场景 | 一个园区、一条街，走完为止 | 两小时逛不完、有明显"向左还是向右"的场域 |

一句话：**打卡是清单，故事是地图**；到了故事模式里，"顺序"退化成"主线建议"，不再是走法的真相。

模式名沿用你说的两个词，发布端就叫 `导览模式：打卡 / 故事`，默认打卡；**前台按这个字段选页面组件**（§0.1）。

## 2. 数据模型

### 2.1 核心决定：不加新节点类型，只加一张「去向表」

推荐（方案 A）：包顶层加两个 **optional** 字段。

```ts
export type TourMode = 'checkin' | 'story'

export interface StoryChoice {
  /** 去向节点 id */
  to: string
  /** 选项按钮上的字（可选）；缺省时前台显示「下一步 · 目标节点名」 */
  label?: string
  /** 一行小字（可选），如「约 80 米 · 5 分钟」 */
  note?: string
}

export interface StoryGraph {
  /** 入口节点 id；缺省 = spots[0] */
  entry?: string
  /** key = 出发节点 id，value = 可选去向（个数不限，§7 第 8 行）；无 key 或空数组 = 结局 */
  choices?: Record<string, StoryChoice[]>
  /** 结局节点的标题（可选），纯展示，如「结局 · 井边无人」 */
  endings?: Record<string, string>
}

export interface PublishedAttraction {
  // …现有字段一个都不动
  mode?: TourMode
  story?: StoryGraph
}
```

三条理由：

1. **`spots` 一个字段都不动** —— 坐标、图片、讲解、`prepareMedia` 素材落盘、AI 生成、发布链路全部照旧复用；故事包与打卡包共用同一份节点数据，切模式不需要迁移节点。
2. **两个字段都是 optional** —— 存量三个包（红山动物园 / 乐山大佛 / 豫园）不改一个字节仍能加载，见 §5。
3. **分支是"关系"不是"节点属性"** —— 单独一张表可以一次性整体校验（悬空 `to`、孤立节点、自环都扫得出来）；挂在每个节点上则要遍历全表才能回答"谁到得了谁"。

备选（方案 B）：`Spot.choices?` 挂在节点上。编辑时更就近，但 `spots` 数组顺序的语义会被悄悄改写（打卡靠顺序、故事不靠同一个字段），而且 `Spot` 是整条进发布包的，加字段就是改契约。**不推荐**。

备选（方案 C）：`story.nodes` 另起一套故事节点。会和 `spots` 重复一份坐标 / 图片 / 讲解，素材落盘要照顾两处映射。**不建议**，除非以后要做"同一个景点、两套讲解"。

### 2.2 一个关键洞察：打卡是故事的特例

"打卡 = 每个节点只有一个去向（下一个）"。

所以数据层只写**一条图函数**（"这个节点的去向是谁"）：

```
去向 = story.choices[id] ?? [数组里的下一个] ?? []   // 打卡包 story 缺失 → 纯数组串链
```

打卡包的 `story` 缺失 → 按数组顺序**隐式串链**（`i → i+1`，最后一站即结局）。注意：**共用的只是这条图函数，不是页面**（§0.1）：

- **打卡页**（原样不动）：去向 1 个 → 手动/自动照旧推进，这是今天的回归基线；
- **故事页**（§3）：去向几个都**列成按钮等人点**，单路径也不例外，绝不自动前进；
- `mode` 决定**前台用哪个页面组件**，不改变数据结构；
- 故事包的 `story` 写坏了（`entry` 悬空 / `choices` 为空）可**降级成打卡顺序**照常导览，不白屏。

（"共用图函数、不共用页面"这一刀让数据层零分叉，只有界面层分成两个页面。）

### 2.3 发布包里长什么样（举例）

以红山动物园改成故事版为例：

```json
{
  "mode": "story",
  "spots": [/* 11 个节点，结构与现在完全一致 */],
  "story": {
    "entry": "spot-mvaxdqn7-1",
    "choices": {
      "spot-mvaxdqn7-1": [
        { "to": "spot-mvaxdqn7-3", "label": "往东 · 去看袋鼠", "note": "约 120 米 · 3 分钟" },
        { "to": "spot-mvbb28ds-9", "label": "往西 · 考拉馆", "note": "约 200 米 · 5 分钟" }
      ],
      "spot-mvaxdqn7-3": [
```

## 3. 运行期（导览页）怎么走

前置结论见 §0：**前台是两个独立页面，故事页没有自动模式，推进全靠左下角选项。**

### 3.1 页面拆分：两个兄弟组件 + 一份共用底座

- 路由不变，仍是 `/tour/:id`，但路由元素换成一层很薄的 **`TourRoute`**：先 `loadPublishedAttraction(id)` 拿到包，再按 `mode` 渲染 `TourPage`（`mode !== 'story'`，打卡页行为一行不改）或 `StoryTourPage`（新组件），并把**已加载的包作为入参传下去**。
- 为什么不各自加载：`/tour/:id` 现在是 `TourPage` 自己 fetch（[TourPage.tsx:145](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L145)）。若 `TourRoute` 先读一次、页面再读一次，会连着闪两次载入（「正在载入…」→「正在载入地图…」），而且同一份 JSON 白拉两遍。所以打卡页只加一个**可选入参**（有就用、没有就照旧自己 fetch），其余一行不改。
- 两个页面是**兄弟**，不是一个组件的 `if` 分支。**共用**的东西抽出来复用、不复制：
  - `AmapLiveMap`（地图 / marker / 路线）；
  - `speak()` / `findChineseVoice` / `estimateSpeechMs`（语音）；
  - `routeTo` + `animateAlongPath`（走过去的路网动画，[TourPage.tsx:296](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L296)）；
  - "这个节点的去向是谁"的图函数（§2.2）；
  - `checkProximity`（靠近触发，[TourPage.tsx:196](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L196)）——故事页只用它做"走近就能看到这个点的情节"，**绝不用它推进**。
- 注意：`AmapLiveMap` 本来就是独立组件，直接 import 就是共用；但 `speak()` / `routeTo` / `animateAlongPath` / `checkProximity` 目前都是 **`TourPage` 里的内联函数**（不是 lib）。怎么共用见 §7 第 12 行。**已落地：抽成 `src/lib/tourLive.ts`（`walkAlongPath` / `speakOnce` / `haversineMeters` / `findChineseVoice`），故事页已用；打卡页暂未切过去，见 §7 第 12 行。**
- **不复用**的是：页面骨架（顶栏 / 底栏 / 进度条 / 左栏）与推进状态机。打卡页那套 `manual ↔ auto`、`nextChapter = chapter + 1`（[TourPage.tsx:386](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L386)）的巡航，故事页**整个不要**。

### 3.2 页面布局：地图打底，右上角情节、左下角选项

地图仍占整屏（复用 `AmapLiveMap`），两块浮层相对打卡页换了位置与角色：

- **右上角 · 当前情节**：常驻卡片，显示当前节点名 + 讲解正文（排版可复用 `SpotContentPanel`，或直接渲染节点的 `description`）。它是故事页的信息重心，替代打卡页把内容压在底部卡片的做法。**2026-10-17 用户标注「这个要给一个收起的按钮」**：卡底栏左侧那行状态字（`当前情节 / 正在走过去… / 自由漫游中`）变成开关，点一下只留 50px 高的底栏，把地图让出来；`重播 / 停止` 两种状态下都在（收起时口播可能还在念）。收起/展开是用户的显式选择，**走到下一个节点不会自动展开**。
- **左下角 · 去向选项**：当前节点的每个可选去向一个按钮（`label` 主行 + `note` 小字）。**这是故事页唯一的前进入口。**
- 单路径（只有一个去向）：左下角就一个按钮，文案兜底「下一步 · <目标名>」（对应 §2.1 里 `label` 缺省的约定）。
- 结局节点（无去向）：左下角换成结局动作 —— `重新开始`（回 `entry`）/ `自由漫游`（放开地图，点哪走哪）。注意打卡页那个 `exitAutoToManual`（[TourPage.tsx:188](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L188)）是"从自动退回手动"，故事页没有自动可退，**名字别照抄**。
- 结局节点还有一块**结算画面**（2026-10-17 加）：走到结局、该节点的口播讲完，整屏压一块遮罩（结局标题 + 本趟足迹 + `重新开始`），点空白关掉就回到上面那张结局卡。详 §11.2。
- **没有「手动 / 自动」切换开关** —— 故事页根本没有自动这条线（§0.2）。

### 3.3 推进：没有自动模式，每一步都点选项（单路径也是）

故事页没有 `manual / auto` 巡航，状态机很短：

1. 进入一个节点 → 右上角显示该节点情节 + **语音播报**（§3.4）；
2. 用户点左下角某个去向 → `routeTo(该节点)` 走过去（复用打卡页的 `routeTo` + `animateAlongPath`）；
3. 到达 → 记进「已走过」，回到第 1 步；
4. **单路径也停在"等人点下一步"** —— 只有一个去向时它仍然是一个按钮，不自动走。这是与打卡页最直观的区别，也是你要的"一切都靠用户选择"；
5. **不回头**（已拍板）：左下角**只列没去过的去向**，去过的节点不再出现；想回已走过的地方，就点「重新开始」回入口重走 —— 故事模式要的是"选择不可逆"的重量；
6. 当前节点没有去向 → 结局 → 左下角出结局动作。

边界：**若某个节点的去向全被第 5 条过滤光了**（都去过了），按结局处理，左下角只出「重新开始」（这条是按"不回头"推出来的，不合意改一处即可）。

> **已落地（2026-10-17）**：第 6 步的结局块实际给了两个动作 —— **重新开始**（回入口，瞬移 + 重播）与**自由漫游**（放开地图，点哪走哪；只在结局块出现）。边界那条按"结局处理"实现了：去向被过滤光的节点走的就是结局块，标题仍按 `story.endings[id]`（多半没有 → 「故事结束」）。

副作用（好事）：**循环分支（A→B→A）天然安全** —— 每一步都是人在点，不会"自动绕圈"；再加上第 5 条，绕回去的按钮根本不会出现。

> 旧稿里"自动模式遇到多分支必须停下等人选"（原 §3.2）**作废** —— 既然没有自动模式，这条规则就不需要了。仅当日后要给故事页重新加自动巡航时才需要它。

### 3.4 语音播报：进入节点就念，和打卡页同一套

- 复用打卡页的 `speak()`（`window.speechSynthesis` + `SpeechSynthesisUtterance`）、`findChineseVoice`，以及 `estimateSpeechMs(text) + 800` 的兜底超时（见 [TourPage.tsx](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx)）。
- 触发时机：**进入一个节点就播报该节点情节**（含"重新开始 / 继续自由漫游"后回到的节点）。用户点选项走过去的过程中不打断，到达新节点再念新的。
- 预留「停止播报 / 重听」小按钮（打卡页已有 stop 逻辑，直接搬）。

> **已落地（2026-10-17）**：右上角情节卡底部就是「重播 / 停止」。实现上把播报收成**一个 effect**（`[currentId, speakToken, pkg]`），"重播"= `speakToken + 1` 逼它重跑 —— 这样"走到新节点"与"原地重听"走同一条路，不会出现"抵达时播两遍"。

### 3.5 地图：从「全铺」改成「迷雾」

现状是一次性把 `spots` 全建成带序号 1..N 的 marker（[AmapLiveMap.tsx:150](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/components/AmapLiveMap.tsx#L150) + [AmapLiveMap.tsx:25](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/components/AmapLiveMap.tsx#L25)）。还没选就看见全部 11 个点，故事模式当场被剧透。

实现口径（不读代码容易踩的两个坑）：

- marker 只在**初始化那一次 effect** 里建成，之后的 effect 只对**已存在**的 id 调 `setContent`（[AmapLiveMap.tsx:224](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/components/AmapLiveMap.tsx#L224)）。所以"点会随进度增减"必须先把建 marker 的逻辑抽成一个可重复调用的同步函数（新增 / 更新 / 删除三件事都做），否则后出现的点根本不会画出来。
- 圆牌上的字现在是**数组下标 + 1**（`spotHtml(index, name, active)`）。故事模式没有 1..N 的语义，得加一个「圆牌文字由外部给」的入参：给字符串就显示，给空串就画个纯圆点，给 null 就不出现这个 marker。打卡页不传这个入参，表现一字不变。

推荐做法：入参从 `spots` 扩成 `spots` + 一个**可见集合/状态**（`unknown | visited | current | reachable`），三层表现 —— 已走过（灰、不带序号）/ 站在哪（蓝）/ 下一步能去哪（黑 + 名称）；`unknown` 不建 marker。再给一个「显示全部」小开关，默认关（照顾"我就想看整个园区"的人）。

代价：`AmapLiveMap` 的 marker 生命周期要从"一次建成"改成"跟随集合增删"，约 20~30 行，顺带序号渲染按模式切换。

省事退路：**全部点照常显示、只是不显示序号**，改动最小，但故事感的悬念就没了。如果不接受迷雾，这是退路。

> **已落地（2026-10-17）**：选了"迷雾"这一条 —— `markerLabel` 入参 + `syncMarkers()` 建 / 改 / 删（§11 第 3 条）。实际只做了两层表现（**当前**=蓝点、**能去的下一站**=黑点 + 名字；已走过与未知都不建 marker），三层里的"已走过灰点"没做，原因见 §7 第 14 行。

### 3.6 路线面板 / 进度条：故事页不复用打卡页那套

打卡页左栏是「路线」面板，把 `nodes` 顺序列出（[TourPage.tsx:686](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L686)）—— 这在故事模式里等于把整张分支图剧透光。**故事页不做这个面板**：

### 4.4 发布门控：在现有 `allWritten` 上加故事模式校验

现状是 `writtenCount === spots.length` 才能发（[PublishEditorPage.tsx:394](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/PublishEditorPage.tsx#L394)）。故事模式再加三条**硬**校验，不通过就禁用「发布」并在 `title` / toast 里指路：

1. `entry` 指向存在的节点（缺省 `spots[0]` 也算通过）；
2. 每个 `choices[x].to` 都指向存在的节点（无悬空引用）；
3. **没有孤立节点**：每个节点都能从入口走到（防止"精心写了一段永远到不了的讲解"）。

回边 / 自环（A→B→A、A→A）**不拦**（不报错），但要**标出来提醒**：运行期"不回头"（§3.3 第 5 条）会让这类去向按钮永远不会出现 —— 作者得知道这一段是死选项，不是通不了的 bug。

## 8. 验证清单（浏览器）

1. 把探索草稿切到「故事」→ 阶段二列表头出现 `入口 / 结局` 信息；连一条 `A→C`（跳过 B）→ 只连这一处就能发布（其余按数组顺序隐式接链）。
2. 门控：把 C 的文案留空 → 「发布」禁用且提示指向 C；补完 C → 可发布。
3. 前台（故事页）：打开故事包 → 右上角出现 A 的情节且**语音播报**；左下角列出两个去向按钮 → 点 C → 走过去 → 右上角换成 C 的情节 + 播报 → C 无去向 → 左下角出结局动作 → 点「重新开始」回到 A。
4. **单路径也要点下一步**：连成 A→B→C 一条链 → 每一步都停着等用户点「下一步」，**不会自动前进**。
5. **不回头**：从 A 走到 B 后，B 的去向里**不再出现 A**（已走过）；要把 A 再走一遍只能点「重新开始」回入口。
6. **没有自动模式**：故事页找不到「手动 / 自动」切换，地图与情节不会自己动。
7. **回归基线**：打卡包（`mode` 缺失）前台**完全不变** —— 仍是 手动/自动 那套、进度条、左栏路线面板都在。
8. 迷雾：地图上只出现「当前 + 能去的下一站」，已走过的不再出现（与第 5 条一致）。
9. **兼容**：存量三个打卡包（红山动物园 11 站 / 乐山大佛 / 豫园）前台打开一切正常（`mode` 缺失 → 打卡页）。
10. **降级**：把某个故事包的 `story` 手工删掉再打开 → 按顺序线性走完、不白屏、控制台有 warn。
11. 孤立节点：造一个谁都到不了的节点 → 阶段二发布被拦；手改 JSON 绕过校验 → 前台忽略它、不卡死。

### 11.5 情节卡文案长过 16:9 会被剪掉（2026-10-17 修）

> 用户标注（情节卡顶部那行小字，红框圈住）：**「这部分的字好像有问题」**。

**病根**：情节卡那张 16:9 图是「一个定高盒子 + 三个绝对定位叠层」（`img` / 渐变 / 文案层全是 `absolute inset-0`）。盒子高度只由 `aspect-presentation`（16/9）决定，绝对定位的文案层**不参与撑高**，于是文案一多，`justify-end` 就把整摞文案往**上**顶、越过盒子上沿，被盒子的 `overflow-hidden` 切掉 —— 最上面那行诗意副标题（`text-xs text-white/70`）只剩几像素残影，看着就是「顶部有行坏字」。

- 复现（真实节点，不需造数据）：`/publish/attr-mvbsg4kw/preview` → 开始 → 选「从刺猬花园的落叶堆里穿」走到 **刺猬花园**（该节点 3 条长 bullet）。文案摞高 **211px**、可用区只有 **179px**（219 − 上下各 20 的 `p-5`），越顶 **32px**：诗意副标题 rect 落在 `y68..84`，而图盒顶在 `y79` —— 只画出 5px；`document.elementsFromPoint` 在 `y71` 命中的是外层滚动容器、在 `y83` 才命中那个 `<p>`，即**上沿确实被裁**。
- 对照：`猴山` 那种短 bullet 的节点撞不到（文案摞 142px < 179px），所以只有素材写得长的节点才露馅。

**改法**（`StoryTourPage` 那个图盒，改动只在结构层）：图盒由 `aspect-presentation relative` 改成 **`relative grid`**，文案层从 `absolute inset-0` 改成 **在流里的一格**（`relative col-start-1 row-start-1 self-end p-5`），并在同一格里放一个空的 **16:9 占位块**（`aspect-presentation col-start-1 row-start-1`）。这样：

| 情形 | 行为 |
|---|---|
| 文案短于 16:9 | 行高 = 占位块的 16:9（**仍是 219**），文案 `self-end` 贴底 —— 与改前逐值一致 |
| 文案长于 16:9 | 行高由文案那一格顶高 → **图盒整体长高**（219 → 250），文案完整显示，`object-cover` 把照片多裁一点 |

> 试过没走通的两条路：`display:flex` 或 `display:grid` 的盒子挂 `aspect-ratio` 时**不会**被内容撑高（实测都停在 221 且内容越顶）；`min-height:100%` 的文案层会和外层高度互为因果，浏览器按 16:9 定死、内容照样溢出。**只有「普通块级盒子 + 内容在流里」才会长高**，再靠 grid 同格叠放拿到贴底。
