# 预览页：编辑与发布之间加一站，发布统一收到这里

> 状态：**已落地**（2026-10-17）
> 起因：用户附件标注两个屏头部的「发布」按钮 —— 「这俩发布按钮换成预览按钮进入点击后进入预览界面，在预览界面统一点发布」
> 涉及：`src/pages/PublishPreviewPage.tsx`（新）、`src/App.tsx`、`src/pages/PublishEditorPage.tsx`、`src/pages/content/{ContentCheckinPage,ContentStoryPage,PublishContentPage}.tsx`

## 1. 一句话

三个编辑屏页头的「发布」全部撤掉，换成「**预览**」→ 跳到 `/publish/:id/preview`，那里按**前台本尊**跑一遍这份草稿（打卡包走打卡页、故事包走故事页），页面右下角浮一条小胶囊：`预览中 · 退出预览 · (去前台看) · 发布` —— **发布只剩这一个入口**。

## 2. 改之前是什么样

「发布」按钮本来有三处，每处一段自己的 `onPublish`（[doc-01 §5 第 4 条](file:///D:/Users/qmruan/Desktop/item/tour-hub/docs/note/01-%E5%8F%91%E5%B8%83%E7%BC%96%E8%BE%91%E5%99%A8-%E5%9C%B0%E5%9B%BE%E9%80%89%E7%82%B9%E4%B8%8E%E5%86%85%E5%AE%B9%E5%88%9B%E4%BD%9C.md) 当年就写着"两处各留十来行，等真出现第三处再合并"）：

| 屏 | 路由 | 按钮状态 |
|---|---|---|
| 阶段二 · 地点与内容 | `/publish/:id` | 「发布」，`!allWritten` 时禁用 + `title` 说原因 |
| 内容创作 · 打卡 | `/publish/:id/content` | 「发布」，`busy` 时禁用 |
| 内容创作 · 故事 | `/publish/:id/content` | 「发布」，`busy \|\| storyBlockers.length > 0` 时禁用 + `title` |

三处都能发，发出去的却是同一份东西 —— 也就没有一个"发之前先看一眼"的地方：

## 3. 现在长什么样

- 三处按钮一律改成「**预览**」（样式不动，仍是蓝底实心；`busy` 时才禁用）。点它跳 `/publish/:id/preview?from=map|content` —— `from` 记着是从哪个屏进来的。
- 预览页右下角一条小白胶囊（`bottom-4 right-3`，`z-[60]`，浮在前台自己的版位之上）：
  - `预览中`（灰字标签，说明这不是真前台）
  - `退出预览` → 回 `from` 指的那个屏（map → `/publish/:id`，content → `/publish/:id/content`）
  - `发布`（蓝底）—— 门控沿用原口径，见 §5
  - 发布成功后胶囊里多一个 `去前台看`（`/tour/:id`），就地提示「已发布（N 张图）」，**不跳走**
- 前台页本身的 `返回 / 问线索 / 手动·自动 / 开始` 全部照旧 —— 预览就是拿真页面跑，不做"简化版"。

## 4. 预览怎么拿到这份草稿（关键）

`ensureEditableDraft(id)` 读草稿 → `toSelfContainedPackage(draft)` 在**内存里**把它拼成一个自包含包（`assets` 里是 data URL）→ 按 `pkg.mode` 渲染 `TourPage` 或 `StoryTourPage`，分发规则与 `/tour/:id` 的 `TourRoute` 一字不差。

这么做换来三件事：

1. **不写 `public/spots`**：预览不产生任何落盘副作用，随便点、随便退。所以"预览随时可进"才成立（草稿只有一半也能看）。
2. **不依赖开发服务**：`toSelfContainedPackage` 本来就是"开发服务不可用"时的兜底路径（[draftStore.ts:324](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/draftStore.ts#L324)），预览复用它，写盘失败也照样能预览。
3. **与发布结果同源**：正式发布走 `toPublishedPackage`，两者只差"图片是路径还是内联"，页面结构、`mode/story/visitorAvatar` 字段完全同一条代码路径 —— 预览里看到的就是发出去的。

代价：图片要先读一遍再内联成 data URL。实测（草稿 11 个节点 + 头像，图已在本机 HTTP 缓存里）从切路由到界面出现 **约 0.15s**；冷缓存会慢一些，`正在准备预览…` 期间有占位。

## 5. 发布门控（回答：预览随时可进，发布按老规矩禁用）

门控从编辑页的按钮上**搬**到预览页的 `发布` 上（不是复制一份逻辑，编辑页那份删了）：

- 节点文案没写全 → 禁用，`title` = `所有节点都写过文案后才能发布（x/N）`（沿用 `isSpotPlaceholder`，与列表里「已编辑 / 未编辑」同一口径）
- 故事模式还有 `validateStoryGraph` 的 error → 禁用，`title` = 该条 message
- 没有任何节点 → 根本进不来（`PublishPreviewPage` 发现 `spots.length === 0` 直接回阶段二）

编辑页仍保留各自的"还差什么"提示（阶段二左栏 `已编辑 N/M`、故事页分支检查红字），只是不再靠按钮的禁用态表达。

## 7. 顺手清掉的东西

## 10. 开场取景：预览 / 漫游照作者框的那一眼（2026-10-17）

> 用户标注：「预览和漫游时需要和发布时的地图在页面上的相对位置和zoom一致（目前是已游客起点为中心）」
> 涉及：`src/lib/tourPackage.ts`、`src/types/attraction.ts`、`src/lib/draftStore.ts`、`src/components/PublishSpotMap.tsx`、`src/components/AmapLiveMap.tsx`、`src/pages/{PublishEditorPage,TourPage,StoryTourPage}.tsx`（决策表见 [doc-01 §5 第 24 条](file:///D:/Users/qmruan/Desktop/item/tour-hub/docs/note/01-%E5%8F%91%E5%B8%83%E7%BC%96%E8%BE%91%E5%99%A8-%E5%9C%B0%E5%9B%BE%E9%80%89%E7%82%B9%E4%B8%8E%E5%86%85%E5%AE%B9%E5%88%9B%E4%BD%9C.md)）

改之前：**`zoom` 已经是通的**（阶段二 `onZoomChange` 实时写 `draft.zoom`，发布时进包），**中心不通** —— 前台两页都写死 `start={pkg.start}`，而 `AmapLiveMap` 拿这个 `start` 既当游客标记位置、又当开场视野中心，所以漫游永远"以游客起点为中心"，与作者在阶段二框的画面无关。

现在：

- **`view?: LngLat`**（草稿与发布包都加，可选）。来源是阶段二地图的每一次落定：`PublishSpotMap` 新增回调 `onCenterChange`，`moveend` 触发（`zoomend` 里也补报一次），阶段二 `updateDraft({ view: pos })`。发布链不用额外传参，`publishDraft` 里 `{...item}` 自然带过去；`viewField()` 保证**没框过就不写这个字段**（不是写 `undefined` 占位）。
- **`AmapLiveMap` 加可选 `center`**：`const viewCenter = centerRef.current || origin`，只喂给建图时的 `center`；游客头像 marker 与 `moveVisitor` / 算路的原点**仍是 `start`**。所以视野中心与玩法彻底解耦。
- **两页各一行**：`TourPage` 传 `center={mapCenter}`（`mapCenter = tourView || tourStart`，并进了地图的 `key`）、`StoryTourPage` 传 `center={pkg.view || pkg.start}`。
- **编辑器自己也照 `view` 开局**：进页面用 `setMapCenter(item.view ?? item.start)`，`goStage2` 的 200ms 那次 `setCenter` 从 `working.start` 改成 `working.view ?? working.start` —— 否则框好的视野一退出就丢，还会被 `moveend` 回写成 `start`。
- **老包不用重发**：存量三个包都没有 `view`，前台走 `?? start` 那条分支，与改动前逐像素一致。

### 实测（浏览器，2026-10-17）

用一个**一次性探针草稿**（复制豫园、`id` 改 `zz-verify-view`）做 A/B，全程没碰用户的真草稿，事后按字节还原（草稿键 45389 字节逐字相同，探针草稿删除、`sessionStorage` 清空）：

- **A（带 `view`）**：`view = start + (0.0008 lng, 0.0012 lat)`（约 154m 东北）→ 预览页里**游客起点那枚标记落在容器中心 (−235.5, +413.5) px**；由这个位移反解出的 `metersPerPx` 回算 **zoom = 18.66**，与草稿 `zoom` 相同；位移比 dy/dx 实测 1.756、按经纬折算 1.754。
- **B（同一探针，删掉 `view` 重开）**：标记回到**正中心 (0, 0)** —— 两个分支的差值就是 `view` 本身。
- **取景是怎么被记下来的**：阶段二点一次节点行（点春堂），AMap 触发 `moveend` → 草稿里出现 `view = {lng: 121.492406, lat: 31.227464}`，与该节点坐标逐位相同。
- **存量包无回归**：`/tour/yuyuan`、`/tour/attr-mvbsg4kw`（包里都没有 `view`）开场时游客标记仍在容器正中。
- `npx tsc -b` 通过、`npx oxlint src` 仍是 9 warnings / 0 errors（`centerRef` 的赋值按 `labelRef` 的先例放进 effect，没在渲染期写 ref）、`npm run build` 通过（JS 427 → 428 kB）。

### 已知边界

视野中心只保证 **center + zoom** 一致。编辑器的地图被左栏挤窄（约 1055px 宽）、前台是全宽，同一 center/zoom 下节点的**绝对像素位置仍会不同**（前台看到的地面范围更宽）。要"连相对位置都一样"就得按容器尺寸反算 zoom 或整块平移，那是另一件事。
