## 1. 一句话

前台是**纯静态**（`catalog.json` + `{id}.json` + 图片），发布端要的"后端"其实只有一件事：**把发布产物写到前台能读到的地方**。所以不做业务服务，只做一个**带鉴权的写入门面**——接管现有 5 个 `/__trip_guide/*` 端点，把 `fs` 落盘换成往静态站点那个 COS 桶里写对象。前台读路径一行不用改。

## 2. 现在是什么样

两条路，一条已经能上云，一条只活在 dev server 里：

| | 谁在读 / 写 | 现状 |
|---|---|---|
| **读**（前台列表与漫游） | `catalog.ts` → `siteUrl('/spots/catalog.json')`、`siteUrl('/spots/<id>.json')`；图片同理 | 静态文件，相对 `BASE_URL`（`vite.config.ts` 的 `base: './'`），**挂根域或子路径都行**，上云零改动 |
| **写**（发布 / 删除 / 恢复） | `exportTarget.ts` 5 个 fetch；实现在 `vite-plugin-export-to-display.ts`（Vite dev server 中间件），落盘 `public/spots` 与 `.trash/spots` | **只在 `npm run dev` 里存在**，`configureServer(server)` 注册 |

打包后静态站点上一打 `/__trip_guide/export` 会命中 404 回退页（返回 HTML）、`res.json()` 直接抛错，`publishDraft` 的 catch 接住 → 走 `toSelfContainedPackage` + 下载 `<id>.json` 与 `catalog.json` 两个文件（图片内嵌 base64）。**功能不算坏，但线上发一次得手工把包塞回 `public/spots` 再重新部署一次**（[draftStore.ts:415](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/draftStore.ts#L415)）。

草稿本身在 `localStorage`（`trip-guide:drafts:v1`），本来就是每浏览器一份，与后端无关。

## 3. 后端要解决的 4 件事

1. **写入发布包**：图片二进制 + 包 JSON，落到前台读得到的静态源
2. **删除 / 回收站 / 恢复**：现有语义是「移入 `.trash/spots/{id}/` 可恢复 + 从 catalog 摘掉」，要 1:1 保留（[doc-01 §5 第 22 条](file:///D:/Users/qmruan/Desktop/item/tour-hub/docs/note/01-%E5%8F%91%E5%B8%83%E7%BC%96%E8%BE%91%E5%99%A8-%E5%9C%B0%E5%9B%BE%E9%80%89%E7%82%B9%E4%B8%8E%E5%86%85%E5%AE%B9%E5%88%9B%E4%BD%9C.md) 拍过：删除必须可逆）
3. **鉴权**：现在端点只在 localhost 上，没有任何身份概念。**公网暴露后不加鉴权 = 任何人能发布、删除你所有景点**
4. **AI 代理（顺手）**：三处 AI 调用（[aiDraft.ts:352](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/lib/aiDraft.ts#L352)、[AskAiPanel.tsx:51](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/components/AskAiPanel.tsx#L51)、[TourPage.tsx:526](file:///D:/Users/qmruan/Desktop/item/tour-hub/src/pages/TourPage.tsx#L526)）是**浏览器直连** `VITE_DEEPSEEK_BASE_URL`。那个地址是 `ada-cli-golang.ctripcorp.com`，内网域名，公网客户端一般不通（需实测）；且 `VITE_*` 构建期内联，key 谁都能从线上 JS 里扒出来。既然都要上后端了，把它一起收进函数、key 只留在服务端环境变量里，是最省事的解法

## 4. 后端放哪：三个方案

**A. COS 站点 + 云函数 SCF（+ API 网关）—— 推荐**
站点与数据同桶：`index.html`、`assets/*`、`spots/*` 都在一个桶里，CDN 直接吃。写接口是 SCF 上一个 Node 函数，用 COS SDK 往同桶 `spots/` 前缀写。发布产物写完**立刻就是前台的静态数据**，前台零改动、无额外延迟。
代价：5 个端点的 `fs` 要改写成 COS 语义（约 200 行，见 §7）；CDN 缓存要配（见 §8）。
一天发几次的用量，存储与请求都在免费额度里，函数按量几乎为零。

**B. 轻量应用服务器（CVM）+ Node 服务 + Nginx —— 改动最小**
插件逻辑几乎照搬：`configureServer` 换成 Express/Fastify 中间件，仍是写本机磁盘。Nginx 既托管 `dist` 又反代 `/__trip_guide`。
代价：要运维一台机器、SSL、进程守护；发布数据在本机磁盘上，备份得自己管。优点是可以马上跑起来，也方便挂 AI 代理。想做这一轮过渡可以选它。

**C. CloudBase 静态托管 + 云函数**
一体化、自带域名与 HTTPS，但数据要另找地方存（数据库 / 存储桶），等于把「同桶同源」这个最顺的结构扔掉，前台读路径得跟着改。不推荐。

## 7. 后端要做的事

### 7.1 契约照搬这 5 个端点

| 方法 | 路径 | 入参 | 现在落到（fs） | 后端要落（COS 对象） |
|---|---|---|---|---|
| POST | `/__trip_guide/media?path=<rel>` | 图片二进制 body | `public/spots/<rel>` | `spots/<rel>` |
| POST | `/__trip_guide/export` | `{package}` | `<id>.json` + merge `catalog.json` | `spots/<id>.json` + `spots/catalog.json` |
| DELETE | `/__trip_guide/spot?id=` | — | 移入 `.trash/spots/<id>[-时间戳]/`，摘掉 catalog | copy 到 `.trash/...` 再 delete |
| GET | `/__trip_guide/trash` | — | 列 `.trash/spots` 下目录 | 列同前缀 |
| POST | `/__trip_guide/trash/restore?folder=` | — | 搬回 `public/spots`，catalog 按 `publishedAt` 插回 | copy 回 `spots/` 再 delete |

**校验一个都不能少**（现在这些挡的是路径穿越，换到 COS 就是 key 前缀穿越）：`SPOT_ID` 正则 `^[A-Za-z0-9][A-Za-z0-9._-]*$`、保留名 `catalog`、图片扩展名白名单、`path` 不允许以 `/` 开头或含 `..`、最终 key 必须落在 `spots/` 前缀内。

`mergeCatalog` / `toCatalogEntry` / `resolveCover`（[:85-118](file:///D:/Users/qmruan/Desktop/item/tour-hub/vite-plugin-export-to-display.ts#L85)）是纯函数，直接搬。

### 7.2 fs → COS 的实际工作量在这几处

| 现在 | COS 上怎么等价 |
|---|---|
| `fs.writeFileSync` | `putObject`（顺带设 `Cache-Control`，见 §8） |
| `fs.readFileSync` + `JSON.parse` | `getObject`（复用 `readJson` 的"读不到就当没有"语义，别抛） |
| `fs.renameSync` 进/出回收站 | **COS 没有 rename**：`copyObject` + `deleteObject` |
| `fs.readdirSync` 列回收站 | `getBucket` + `Prefix`/`Delimiter`；图片是**多个**对象，得先 list 再逐个 copy/delete |
| `fs.statSync().mtimeMs` 当 `trashedAt` | 对象的 `LastModified` |
| "目录"（`<id>/` 图片目录） | 前缀 `spots/<id>/` |

一处要注意：`catalog.json` 的 merge 是 read-modify-write，函数并发下理论上会丢更新。演示量级可忽略；要稳就用对象 ETag 做条件写，或给这条路径串行。

### 7.3 鉴权（第 3 条）

最小实现：函数环境变量里存 `ADMIN_TOKEN`，每个写请求校验 `Authorization: Bearer <token>`，不对就 401。前端 token 存 `localStorage`，`GET /__trip_guide/trash` 也一起保护。

> SCF 访问 COS **用函数角色（CAM 角色）授权**，不要把 `SecretId`/`SecretKey` 写进环境变量。

## 8. 部署与配置要点（选 A 时）

1. **构建**：`cp .env.example .env` 填好 → `npm run build`，产物 `dist/`。`.env` 不在仓库里，但**必须在构建前就位**（`VITE_*` 是构建期内联）。
2. **桶**：建一个 COS 桶（就近地域），开启静态网站，索引文档与错误文档都设 `index.html`。HashRouter 路由在 `#` 后面，**不需要 SPA history 回退**。
3. **上传**：把 `dist/` **里面的内容**传到桶根（别多套一层 `dist/`）；`coscli cp dist/ cos://<bucket>/ -r` 比控制台点选稳。
4. **Bucket Policy 只放行静态要用的路径**：`index.html`、`favicon.svg`、`logo-dark.png`、`assets/*`、`spots/*` —— **`.trash/*` 保持私有**，否则回收站里的包和图片能被直接猜到地址取走。
5. **CDN 缓存策略**（这条不做，会出现"发了新包前台却看不到"）：
   - `spots/*.json`、`spots/catalog.json` → `Cache-Control: no-cache` 或很短的 TTL（`loadCatalog` 的 `cache: 'no-cache'` 只管浏览器，管不到 CDN）
   - `assets/*`（带 hash 文件名）→ 长缓存 `immutable`
   - 在 `putObject` 时就写进元数据，比事后刷缓存可靠
6. **域名与 HTTPS**：绑自定义域名 → 开 CDN → 申请免费 SSL 证书 → 强制 HTTPS。COS 默认域名不建议直接对外。
7. **高德侧放行**：高德开放平台 → 应用管理 → 「Web端(JS API)」那个 key 的域名白名单加上新域名（https），并核对安全密钥与 `VITE_AMAP_SECURITY_CODE` 一致。
8. **接口接入**（第 2 条选①）：CDN 加一条路径规则，把 `/__trip_guide/*` 回源到 API 网关（不走 CDN 缓存），其余走桶。
