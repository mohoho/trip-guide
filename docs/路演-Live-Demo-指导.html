00怎么用这份文档

这份是按 ppt-prompt.md 重写的主文档。先看 02（模板对比）和 05（分镜表），这两页决定了整个演示的骨架。

如果你是主讲

背 01 的三句定位 + 04 的开场与收尾。中间的 Demo 靠 05 分镜表，不靠背。

如果你是操作手

只看 05 分镜表与 06：什么时间、停在哪个 URL、点哪里、「从头生成」降到哪一步。

如果你主答提问

先看 08 的 A（定位）、B（平台与模板）、C（内容与 AI）三组——这是新定位下评委最集中的三块。

核心变化：从「讲产品」变成「讲平台」 按 ppt-prompt.md，我们的客户是合作伙伴（景区 / 文旅 / 园区），游客是他们的用户。所以全程的主语要换：不是「我们做了一个好玩的导览 App」，而是「我们给合作伙伴一套互动引擎，加一个 AI 辅助创作平台，每个模式各有自己的创作模板」。

01定位：景点内的互动引擎 + 给合作伙伴的 AI 创作平台

开场 30 秒必须把这两层说清：引擎（游客玩什么）和平台（伙伴怎么生产）。

1.1 三句话定位（照念）

第一句 · 引擎程导览是一个「景点内的互动引擎」。
第二句 · 平台它同时是给合作伙伴的一套「互动流程的 AI 辅助创作平台」——内容是伙伴自己生产的，我们提供生产能力。
第三句 · 两种模式目前支持两种互动模式：打卡模式和故事模式，每个模式都有各自的创作模板。

1.2 谁在用（一定要讲清的两层）

角色是谁他们得到什么演示里对应哪一段
合作伙伴（客户） 景区 / 文旅局 / 博物馆 / 园区 / 展会主办方 一套互动引擎 + 一个 AI 创作平台：不改代码，就能把自己场地做成可玩的内容 「生成平台」与「从头生成」两段
游客（最终使用者） 到访的人，用手机浏览器打开 沉浸式路线引导 + 打卡点讲解（打卡模式）；多条路线的趣味探索（故事模式） 「互动体验」段

02两种模式与各自的创作模板

这是新定位里最关键的部分：「两种模式 + 两套模板」要讲得像一个产品结构，而不是两个功能。

2.1 两种互动模式（游客侧）

维度打卡 打卡模式故事 故事模式
一句话走遍每个节点：沉浸式路线引导 + 打卡点背景讲解提供多条路线进行趣味互动，探索不同的路线
走法按节点顺序线性走完，手动漫游或自动巡航路口自己选，去向由故事结构决定，单路径也要人点
地图全部节点铺出来（1…N），有进度条与路线清单迷雾：只露「我在哪」和「下一步能去哪」，不剧透
讲解落点右上角讲解卡 + 顶部进度条右上角「当前情节」常驻卡（可收起）
结束走完最后一站走到没有去向的节点＝结局，有结局结算画面（结局标题 + 本趟足迹）
适合的场景一条街、一个园区，有明确游览顺序两小时逛不完、有「向左还是向右」的场域
演示案例豫园 yuyuan红山动物园 attr-mvbsg4kw（故事《黑神话悟空》）

2.2 两套创作模板（伙伴侧）—— 这是「平台」的证据

两种模式在创作平台里是两个不同的编辑页、两套不同的提示词。这是可以当场演示、也经得起追问的差异化。

模板构成打卡 打卡创作模板故事 故事创作模板
要填什么景点简介 + 每个节点的讲解故事名 + 前情提要 + 每站情节 + 每个去向的选项文案 + 结局标题
AI 写什么简介一段 + 每站一段（标题 / 要点 / 口播稿）故事名与前情提要一段 + 每站一段 + 结构一段（可勾选）
语气第三人称、导览口吻、讲清背景第二人称「你」、叙事口吻、情节要接住上一站留下的悬念
结构编辑节点顺序＝游览顺序，没有分叉有故事结构图（入口 / 分叉 / 结局），AI 可重排走向（节点与坐标不动）
发布门控全部节点写过文案才能发额外要求：结构无悬空、无孤立节点
示例字段「景点简介 + 节点内容」两张卡「故事结构 / 前情提要 / 节点内容 / 这个节点的去向」四张卡
被问「模板和模板之间差在哪」时的标准回答 「不是换套皮肤，是换一套生产流程和提示词：打卡模式的模板产出的是一份带顺序的讲解清单；故事模式的模板产出的是一张有入口、分叉和结局的关系图，还要为每个岔路写选项文案。所以两者的 AI 提示词、校验规则、发布门控都不一样。」

2.3 三个记忆点

① 一个引擎，两种玩法

打卡是「清单」，故事是「路径」。同一份数据、同一套地图与语音，切换零迁移。

② 模式自带模板

每个模式都有自己的创作模板与提示词——伙伴选模式，平台就给他对应的生产流程。

③ 伙伴自己就能生产

输入名字 → 高德找地点 → 拖坐标 → AI 写内容 → 预览 → 发布。不用改一行代码。

2.4 不要说的话

  • ❌ 不要把程导览讲成「一个给游客的 App」——客户是合作伙伴。
  • ❌ 不要说「AI 全自动」。AI 写叙事，坐标、结构边界、最终审核都是人。
  • ❌ 不要说「两种模式随便切」——数据结构上可以，但故事包需要额外连分支、写选项，不是一键切换。
